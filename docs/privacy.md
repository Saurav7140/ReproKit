# Privacy and security contract

## Website SDK (Phase 7)

The optional SDK observes nothing on import/construction. The host must obtain informed consent, then explicitly call start; stop/discard and the visible indicator remain available. It shares extension masking and bounded capture. The separate sample holds one report in page memory and uploads only on Submit after stopping/reviewing/saving details. Reload/navigation loses local evidence, without restart. User-entered report details, retained origins and short test IDs can identify people/apps; inspect before sending. A hostile host can interfere with capture or fabricate payloads, so client masking and a consent boolean are not proof of consent or trustworthy evidence.

Public intake uses a project-routing key and exact allowed Origin, not visitor authentication. Keys appear in client code/requests and may be logged; never use an account token or service secret there. Non-browser callers can forge Origin and exhaust the shared ten-attempt hourly quota or 20 report slots. Limits bound accepted reports, not invocation/network/database costs. Owners can disable/rotate intake; rotation preserves counters, and previously reserved in-flight work may complete. Upstream bot/abuse protection is required before broad public exposure. No CAPTCHA/IP reputation is claimed. The write-only response includes only acceptance and the caller's report UUID, never private read access.

Submitted content enters the same private, owner-scoped Storage with 30-day retention and leased cleanup; the website gets no report reads, status updates or deletion rights. Owners remove submitted reports through the dashboard. Local/downloaded copies and provider logs/backups have separate retention. [Full security model and limits](website-sdk.md#public-ingestion-security-model), [verification](verification-phase7.md).

## Current behavior

The extension records only after an explicit action. Permissions remain `activeTab` and `scripting`, with no persistent host permissions, storage permission, background worker or external messaging. The full review page owns one in-memory report. Content scripts only stream sanitized evidence through a document-scoped port. Both viewers accept local imports/exports. Phase 6 optionally connects the trusted review page to Supabase for an explicit reviewed upload; capture itself stays local. No telemetry is implemented. Fonts are bundled locally. Demo secrets are public synthetic test values, never credentials.

The extension exposes only the trusted static `replay.js` and `replay.css` resources to let an opaque replay document bootstrap. They contain code/styles, never report data. This may allow websites to detect this unpacked extension if they know its ID; no all-site capture permission is granted. The opaque renderer has no extension runtime API.

Closing/reloading the capture page disconnects its port and stops the recorder; the report is lost. Source navigation/reload stops recording and retains already-received evidence in the open capture page. Start parameters are removed immediately so reload cannot restart capture. No service-worker lifetime can lose a recording because there is no recording worker. A browser restart destroys all recording memory. The recorder's idle connection bootstrap remains in the isolated document until navigation, but its DOM observers, interaction/diagnostic listeners, timers and indicator are stopped/removed.

## Implemented capture controls

Explicit user start on one authorized selected tab, with capture explanation, unmistakable persistent recording indicator, stop and discard. No auto-resume, automatic upload, or background all-site access. Never collect cookies, storage APIs, clipboard, authorization headers, request/response bodies or raw console logs. ReproKit UI and requests must be excluded.

All ordinary text is replaced with `[masked]`, including text mutations and input events; checked form state is not retained. Contenteditable, explicit opt-out regions, ReproKit's indicator and unsupported asset/media regions are blocked. Serialized DOM uses a fixed tag allowlist; attributes retain recognized input types, bounded blocked-region dimensions and the validated v3 presentation subset. Original stylesheets, identifiers, locators, CSS strings/variables, active content and external assets are removed. v3 captures retain only allowlisted resolved numeric/enumerated layout values and RGB colours; original font names become generic local families. Every URL path is replaced by `/[redacted]` (root `/` stays root); queries, fragments and userinfo are removed. **Origins remain visible** and can identify a private hostname or tenant. No page titles, raw labels, arbitrary selectors, error messages, rejection reasons or local stack paths are kept. Phase 4 separately retains short unique test-ID tokens and unique control-role enums for reproduction drafts; they are not retained as replay DOM attributes. These identifiers can still reveal application or tenant information. Exceptions retain a category and available numeric line/column; rejection reasons are never read. Environment is coarse OS, browser family/major and bounded viewport dimensions. Masked/blocked regions still exclude descendant styles. Resolved presentation can reveal geometry and visual application state, so inspection before sharing remains necessary. Original fonts/assets, pseudo-elements, transforms and continuous animations may differ.

Sanitization runs synchronously before the extension port and recording buffer; the controller validates packets again and masks diagnostic fields defensively. rrweb snapshots and supported mutations pass an explicit field allowlist. Unsupported channels are dropped. Stop limits are 5 minutes, 10,000 combined evidence/timeline events or 5 MiB serialized report, with reserved generated-step and final metadata space. Each DOM event has a 512 KiB bound, 5,000-node traversal bound and 64-level DOM depth bound. Error and request arrays each cap at 1,000. The page bridge checks source/origin/session, known schemas, primitive field/size bounds and 50 messages/s. Page messages cannot invoke extension controls, storage or upload; valid-looking diagnostics can still be forged or suppressed by a hostile page. The nonce routes a session and is not authentication.

Before real capture verification, the sanitizer/buffer unit checks passed. Real synthetic demo recordings and exported files also pass serialized secret-absence assertions. Automatic sanitization cannot recognize every possible sensitive application value: users must inspect before sharing. User-entered titles/descriptions are exported as entered; imports are validated, not automatically scrubbed of sensitive text.

## Implemented imports and replay

All report content is untrusted. File byte size is checked before reading; the bounded parser then validates UTF-8 size, versions 1/2/3/4, strict structure, JSON nesting (80 levels), field/array bounds and cross-field consistency. Replay events additionally have per-event byte/node/depth limits and viewport dimensions bounded to 16,384 px. A failed read/validation/cancel leaves the open report and its unsaved edits intact. A valid replacement requires confirmation. Cancellation invalidates pending results; the bounded native file read itself may finish in the browser.

UI strings use React escaping, never raw HTML or evaluation. The trusted replay document is a `data:` URL with a unique opaque origin; no report content is interpolated into its HTML. Its sandbox permits scripts and same-origin access for the trusted rrweb driver to access its nested frame, while the data origin remains separate from the dashboard/extension. Captured DOM is rebuilt only inside rrweb's `sandbox="allow-same-origin"` child, without `allow-scripts`. Canvas replay and unsafe rebuild options are disabled. Do not replace the data URL with a same-origin URL or `srcdoc` under those outer sandbox tokens.

The outer document's CSP blocks connections, objects, forms and external assets; only locally bundled renderer JS/CSS, `about:` child frames and trusted data images for the cursor are allowed. Captured tags/attributes/URLs and the strictly validated CSS presentation subset cannot introduce active content or assets. v3 permits only bounded canonical declarations from a property/value allowlist; URLs, functions such as var()/attr(), selectors, arbitrary font names, generated content and custom properties are rejected. The parent accepts messages only from its own frame with opaque origin and the current session token. The driver accepts messages only from its parent. Report validation runs again inside the renderer. The extension permits style attributes via style-src-attr so validated presentation can render in the inherited sandbox policy; script-src and stylesheet-element restrictions remain unchanged. Removing/replacing a report, changing evidence panes or leaving dashboard Reports destroys the replay frame. Synthetic adversarial checks verify parent isolation, absent extension APIs, blocked network and script execution; real captures verify display and playback.

## Retention decisions

- Local capture/import: one report per open viewer in memory. Source navigation/tab closure stops capture and preserves the partial report while its page stays open. Viewer closure/reload, extension reload or browser restart loses the in-memory report and edits. There is no disk recording cache or persistent report list. Stopped capture transfers to the viewer and releases the old recording buffer.
- Local export: explicit download only. A validated UUID determines the filename, not user text. Blob URLs are revoked after download initiation and on viewer unmount. Exported files persist in the user's download location until the user deletes them. Removing a report asks for confirmation, releases its page references/replay, and leaves downloaded files alone; this is not a guarantee of immediate memory zeroization.
- Optional hosted: explicit authenticated uploads only. Reads expire at 30 days. The configured cleanup job removes recording objects through the Storage API before metadata and retains failed/pending work for retry under leases. A real scheduled invocation returned HTTP 200 with one removed report and zero failures; object and metadata absence were verified. The normal schedule is every 15 minutes. Monitor HTTP outcomes/backlog after setup changes or outages. Provider backups may outlive live deletion according to configured provider retention; document that configuration before wider hosted launch.
- Local capture/export/import does not depend on the hosted job.

## Phase 4 locator and source boundaries

Locators are captured only on trusted user interactions outside blocked regions and ReproKit UI. A test ID must be a unique `data-testid` token matching `[A-Za-z][A-Za-z0-9_-]{0,63}`. Otherwise a supported control role is retained only if one visible candidate matches; names/labels are not read. Shadow-root and ambiguous targets receive no locator. Counts are bounded to 5,000 candidates. The recording buffer revalidates locator tokens/enums and continues masking target labels/values. A syntactically valid test ID is not proof it is non-sensitive; the popup discloses this capture and review before export is required.

Draft generation validates the full report, accepts only compatible web actions, quotes every data literal and interpolates no captured values into comments or executable syntax. Unsupported roles/targets/operations and missing/redacted routes produce fixed TODO guards. Text/password fills contain throwing value placeholders, never captured values. Timings are comments; no sleeps, credentials, backend fixtures or expectations are inferred. A final assertion guard prevents an action-only draft from passing. Only the first 97 actions are included, with explicit guarded truncation; generated report steps remain bounded to 100 entries of 1,000 characters.

The viewer displays source in a plain React textarea and downloads it; no eval, dynamic import or execution path exists. User-edited source is not certified safe and must be reviewed before running in a test project. Editor changes survive pane/dashboard navigation but are not embedded in report JSON; removal/reload loses them. Exports use the validated report UUID for filenames and revoke Blob URLs. Actual generated-code execution during verification targets only the controlled local demo, with separately supplied assertions.

## Hosted security gate

Phase 6 extension credentials stay in the trusted open review page's memory (`persistSession: false`, URL session detection disabled). They are not saved in localStorage/sessionStorage/chrome.storage, put into report JSON or links, passed to content/MAIN scripts, or accepted through website messages. Each review page requires its own sign-in with an existing confirmed account; creation/recovery use the dashboard link. Build validation rejects privileged keys and unsafe origins, and limits extension `connect-src` to the configured Supabase origin; unconfigured builds retain `connect-src 'none'`. No host/storage/identity permission was added. Replay retains its separate no-network CSP, opaque origin and script-disabled captured frame.

Disconnect replaces the in-memory client immediately, clears account/projects/link state and attempts server sign-out separately. It preserves the local report offline; server revocation cannot be guaranteed during an outage and issued access tokens follow Supabase expiry. Closing/reloading loses report and connection; export first. Rejected refresh credentials clear expired state. Unsaved details block upload, in-flight duplicate clicks are guarded and server idempotency remains authoritative. Saved dashboard links contain validated project/report UUIDs; the owning account must sign in. Invalid/other-project links do not trigger a recording read.

The server permits CORS for the configured dashboard and syntactically valid Chromium extension origins, reflecting the exact accepted origin. This accommodates different unpacked/store IDs; it does not identify or authenticate ReproKit. Every user operation still needs bearer validation and ownership checks. An extension origin/public key alone returns 401; arbitrary website/opaque origins remain denied. [Phase 6 verification](verification-phase6.md).

With Supabase configured, the dashboard persists its authentication session through the SDK in browser storage, and sends email/password and session tokens only to the configured Auth service. It requests owner metadata after sign-in. Report bodies upload only on **Upload reviewed report**, after saved local details; importing, project selection and sign-in do not upload them. Report title/description and retained origins/test IDs are included as reviewed. Hosted storage is private; the authenticated server issues owner-only signed reads lasting 60 seconds. Treat those URLs as temporary bearer credentials. Signing out clears hosted content from the UI; local/exported copies remain separately controlled. Provider Auth/log/backup retention must be reviewed before real use. The dashboard itself does not record.

The migration and server validation enforce ownership and payload/capacity/rate bounds. Direct client Storage signing/writes/deletes and service mutation RPCs are denied. Account deletion is intentionally restricted while project/report references exist: remove recording objects and report metadata first through the supported operation, then owner/admin-managed project/account records. There is no one-click account-erasure flow in this phase. The authorized backend, Auth redirects, Vault and scheduler are installed; real isolation/deletion/failure recovery passed, and the owner confirmed confirmation/reset emails and links. SMTP configuration was not changed by the agent. [Setup](hosted-setup.md) and [verification](verification-phase5.md).

Server-side ownership checks, RLS on every owner-scoped table, private storage policies, short-lived signed reads, authentication expiry handling, bounded validated ingestion and abuse limits. Test anonymous denial and two-account isolation, cleanup, partial upload failures and retries. Extension tokens must never pass through an arbitrary website message bridge. Report security issues privately to the repository owner; do not include real recordings or secrets in public issues. Owner must select a license before distribution.
