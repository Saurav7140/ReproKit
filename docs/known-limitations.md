# Known limitations and release boundaries

ReproKit prepares bounded developer evidence, not a guaranteed reproduction of an application or a video recording. See the report's own limitations as well as [Phase 8 evidence](verification-phase8.md).

| Area | Current boundary |
| --- | --- |
| Browser/platform | Desktop Chromium extension; top-level secure HTTP(S) HTML. Chrome and Edge checks name exact installed versions in the verification log. Manifest minimum 120 is a technical floor, not certification of every version since 120. Firefox/Safari, mobile/native apps, hardware/device capture, incognito, file URLs, PDFs, stores and browser-internal pages are unsupported. |
| Capture lifecycle | Explicit start only. Full source navigation/reload stops the extension session; no restart. Closing/reloading its review page loses evidence and connection. Website SDK reports live in the source page itself, so source reload loses them. No persistent report cache or browser-wide recording. |
| Capture limits | First of 5 minutes, 10,000 combined events or 5 MiB serialized JSON; error/request arrays each cap at 1,000, diagnostics at 50/s. A DOM event caps at 512 KiB, 5,000 traversed nodes and 64 levels. Resolved styles count toward bytes. Complex pages can end much earlier. These bounds limit retained evidence, not total browser RAM or all work needed to observe a hostile page. |
| Performance | Measurements use synthetic pages on one machine. Changing many styled elements can approach 5 MiB quickly. Frame cost, startup and source heap deltas are not guarantees for real sites, low-end hardware, throttled/background tabs, native browser UI or cloud concurrency. |
| Privacy | Text, inputs, labels, arbitrary attributes, URL paths and diagnostic messages are masked/removed. Origins, short unique test IDs, coarse environment and safe geometry/colours remain. Your title/description are preserved as entered. Neither schema validation nor client masking proves that a deliberately fabricated or manually edited report contains no sensitive text. Review before sharing. |
| Replay fidelity | Masked DOM behavior, not pixels/video. Original fonts, images, frames, media, canvas/WebGL, external stylesheets, pseudo-elements, transforms, continuous animations and unsupported effects may differ or be absent. Old v2 files cannot recover discarded styles; v1 has no replay. No captured scripts, application authentication, original services or backend state are restored. |
| Diagnostics | Completed Resource Timing entries only; methods unknown. Transport failures, aborts, timeouts, unfinished/unconsumed fetch bodies, workers, early errors and hidden cross-origin status can be absent. Page-world diagnostics can be forged/suppressed by a hostile page. No body/header/console/cookie/session-storage capture. |
| Reproduction | Deterministic editable starting point, up to 97 actions. Missing routes, locators, inputs, setup and assertions require manual completion. Unedited TODO guards intentionally fail. A passing click sequence does not prove a bug. The viewer never runs source. |
| Hosted storage | Owner-only projects and private recordings; 25 projects and 100 reports/account, 20 authenticated attempts/hour. Content is immutable; changed payloads under the same source ID conflict. Upload/deletion failures may need a 15-minute lease to expire before retry. Reads expire after 30 days; scheduled batches/physical deletion can lag. Downloads and provider logs/backups have separate retention. |
| Public website intake | Opt-in single exact origin/project, public routing UUID, 10 attempts/hour/intake and 20 retained reports/project, same payload/account caps. Non-browser clients can forge Origin/copy keys, exhaust quota, submit fabricated valid data and incur invocation costs. Rotation preserves quota. Already reserved work can finish after disable. No visitor authentication, CAPTCHA, WAF or IP reputation is provided; add upstream protection before broad exposure. |
| Accounts/accessibility | Dashboard auth persists through Supabase; extension connection is temporary per review page. Offline remote sign-out cannot be guaranteed. Keyboard, labels, modal focus and responsive layouts are checked; a screen-reader/hardware accessibility certification is not claimed. |
| Distribution | Source is MIT licensed and stored in a project-rooted private GitHub repository. Frontend deployment, extension-store submission and registry publication remain separate steps. Public hosting still needs a private security contact and provider/abuse-control review. |

For new hosted projects, apply both migrations in order, install the validator/functions and configure Auth/email/Vault/Cron. Existing manually applied migrations require history reconciliation before CLI db push. Do not reset a live database to make setup tests pass. [Setup](hosted-setup.md), [website SDK](website-sdk.md).
